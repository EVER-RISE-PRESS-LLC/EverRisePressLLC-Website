# Readers and referral partners: admin audit and repairs

27 October 2026. Scope: the existing `/admin/leads`, `/admin/referrals`, and partner detail routes, their client components, reader export, and partner create/update handlers. The work follows `PRODUCT.md`, `docs/DESIGN.md`, and Impeccable’s Operate guidance. It uses the existing Cloudflare D1 database, components, and installed dependencies. No external service, email workflow, paid feature, or database migration was added.

## Concrete findings and changes

| Finding | Repair |
| --- | --- |
| The reader list called every unsynced email “Pending” under “Mailchimp”, suggesting an email integration or queued newsletter that does not exist. | Rename the screen to Readers; remove the misleading sync column; explain that signup opens Chapter 1 on the website and does not send automated email or subscribe to a newsletter. Keep the historical database sync flag intact. |
| Search had a placeholder without a visible label. Book and partner selectors navigated immediately and could discard an email query that had not been submitted. | Provide visible labels and one Apply filters form. Apply all values together, reset pagination, retain applied values in the URL, announce pending/results, and provide clear/reset actions. |
| Readers had no date filter. Empty filtered results used the same copy as a genuinely empty database. | Add inclusive Saved from / Saved through dates, clearly labeled UTC; reject a reversed range in the form; normalize malformed direct URL dates and show a recovery message. Filtered empty results offer Clear filters. |
| An email containing `%` or `_` unintentionally acted as a SQL wildcard. D1 also restricts LIKE/GLOB patterns to 50 bytes, shorter than many valid email addresses. | Use a shared parameterized, case-insensitive literal substring search in the list and export, avoiding the LIKE/GLOB limit. |
| A seven-column reader table was difficult to read on phones and rendered email addresses in small monospace. Pagination showed pages without a record range or pending feedback. | Use readable email text, a five-column desktop table, separate mobile summaries, 44 px controls, visible record ranges, and pagination disabled during navigation. Apply a stable date + ID ordering. |
| Export was a direct download link: authentication or server errors could download as if they were a CSV. CSV cells did not neutralize spreadsheet formulas, and carriage returns were not escaped. | Fetch the file with status and `text/csv` checks, show preparation/success/error feedback, disable empty exports, apply the same filters, neutralize formula prefixes, escape quotes/commas/line breaks, and set `private, no-store`. Rename the misleading `mailchimp_synced` CSV heading to `email_sync_recorded`; the underlying historical value is preserved. |
| The partner table had nine columns, hid the main detail action in a menu, and had no search, status filter, or pagination. | Use five information columns plus actions, direct partner-name detail links, local name/email/link search, active/inactive filter, 15-per-page navigation, mobile summaries, and clear empty states. Explain that counts are all time and can include repeat visits. |
| Share links were computed from `window` during rendering or from an optional environment variable, so a copied detail link could be relative. | Pass the existing canonical `SITE_URL` into the partner list and use it on detail pages so copied links are absolute and consistent. Copying does not visit or increment a referral link. |
| The partner form used “vanity slug” and “Custom UTM”, with no explanation that the latter currently has no effect on tracking. The slug label pointed to a wrapper instead of its actual input. | Rename to Referral link name and optional Internal label, explain their actual behavior, associate the label with the input, give concrete validation errors, cap lengths consistently on client and API, and state that partner creation sends no email. Existing internal values are retained. |
| Changing a link name silently broke old shared links. Closing an edited dialog silently discarded work. Saving could be repeated or the dialog closed mid-request. | Require explicit acknowledgement before saving a changed referral link, confirm discard of unsaved changes, lock controls and dismissals while saving, show inline recoverable errors, and retain entered values after a failed request. |
| Partner deactivation confirmation was nested inside a dropdown menu and could disappear when the menu unmounted. Requests had no pending state and the confirmation closed before failure was known. | Mount the row confirmation outside the dropdown; keep it open during the request and on failure, disable duplicate requests, and explain that existing records remain saved. Deactivation still requires an explicit confirmation. Reactivation stays available. |
| The detail page showed edit/deactivate buttons to users without the ADMIN role, although the API rejected those actions. | Read the current role on the detail page and show mutation controls only to administrators. API role checks remain in place. |
| The “last 30 days” chart generated 31 dates, ran two correlated count queries for every day, and used all-time totals to decide whether recent activity existed. | Use exactly 30 UTC dates including today, two grouped date-limited queries, and a recent-series empty check. Keep all-time totals separate and explain the reader-to-visit rate without implying book purchases or unique visitors. |
| Recent readers and visits were dense tables; repeated timestamps could produce duplicate React keys. Hashed IP fragments were shown without helping the staff task. | Use readable responsive lists with actual record IDs, a View all readers link filtered to this partner, country/referring-source descriptions, and no hash fragments in the interface. Tracking and stored records are unchanged. |
| Duplicate-link races could surface a generic save failure, and database error logging could include bound contact details. | Return a field-specific link conflict for a matching uniqueness error and log only the error class for unexpected partner/export failures. |

## Boundaries and remaining considerations

Partner search/pagination is local after the existing all-partners query; the expected small partner directory needs no extra D1 requests as filters change. Reader filtering and pagination remain server-side. CSV export still intentionally exports every matching reader, and therefore memory/work grows with the matching dataset; there is no silent truncation. For a much larger reader base, a separate batch/stream export design would be appropriate.

The CSV heading rename may require an update to a downstream import script that explicitly expected `mailchimp_synced`. There is still no newsletter sync or automatic email delivery. Referral totals can omit visitors who disable analytics and can include repeated visits. The public referral behavior, cookies, consent, stored records, and tracking remain unchanged. No production database changes, real signups, messages, partner deactivations, commits, pushes, or deployment were performed as part of this scoped work.
