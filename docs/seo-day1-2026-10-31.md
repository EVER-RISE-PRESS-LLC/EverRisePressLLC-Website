## Event definitions and repair

The working primary action is successful chapter access. `chapter_unlock_success` is the browser acknowledgement of an accepted request and signed access cookie; its `is_new_lead` property distinguishes first registration from returning access. It is not an event for every page view of the unlocked chapter.

`lead_generated` is emitted server-side only for a newly stored normalized email and book pair. A returning request emits `chapter_access_renewed`. GA `generate_lead` and Meta server `Lead` also apply only to new registration. Do not add server and browser event totals together, or treat renewals as new leads. A single conditional SQL insert prevents repeated concurrent requests from creating the same lead; existing records and established partner attribution are preserved. Verification and signing must succeed before storing a lead.

`retailer_redirect_click` is a separate secondary action. Each intentional click records one server event and one database click. A later intentional click is another click, not another unique buyer. The browser sends the corresponding GA event to a different platform. Retailer exits are not proof of a completed retailer visit, purchase or sale. No production test subscriber or retailer click was submitted for this audit.

Both actions now receive `landing_path` and `conversion_path`. The first eligible public path is remembered within the browser session. Queries, fragments and private route shapes are discarded; analytics opt-out clears stored landing attribution. Storage restrictions result in missing landing attribution rather than a failed form. Client attribution is descriptive untrusted input, never authorization. Existing analytics and advertising choices remain independently enforced.
